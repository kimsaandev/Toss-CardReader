# Toss CardReader

> 이 포크의 UART 수정 버전은 토스 프런트 1.5세대(PLF02WH)를 커스텀하는 일부 환경에서 발생하는 UART 연결 문제를 해결하기 위해 만들었습니다. 개인 커스텀용이며, 공식 카드 결제는 지원 범위에서 제외됩니다.
>
> 저는 이 기기를 아이들 장난감으로 쓰기 위해 커스텀했습니다.

LineageOS 18.1에서 발생하는 연결 증상, 기존 버전과의 차이, 재부팅 후 실기기 검증 결과는 UART 수정 브랜치에 정리했습니다. [LineageOS 18.1 UART 수정 브랜치](https://github.com/kimsaandev/Toss-CardReader/tree/fix/plf02wh-lineage18-uart)

토스프론트의 IC·마그네틱 리더로 카드를 읽고, 회원 확인과 출입 기록에 활용하는 Android 앱입니다.

**결제 외 용도**로 사용합니다. 결제 승인, PIN 입력, 결제 암호문 생성, 결제 키 관리 기능은 없습니다.

| 항목 | 내용 |
| --- | --- |
| 앱 버전 | 1.3.0 |
| 패키지 | `com.toss.cardapp` |
| 대상 환경 | 토스프론트 PLF02WH / LineageOS 13 |
| 필수 구성 | 없음. Magisk 모듈 없이 리더에 직접 연결합니다. 순정 Sunmi 결제 하드웨어 서비스가 있으면 그 서비스를 사용합니다. |
| 배포 파일 | `toss-front-card-app-1.3.0.apk` |

## 주요 기능

- **카드 읽기**: IC의 EMV 공개 정보와 마그네틱 트랙 정보를 화면에 표시합니다.
- **자동 실행**: 홈 화면에서 카드를 꽂거나 긁으면 리더 화면을 엽니다.
- **회원 확인**: 등록한 카드와 비교해 허용·차단·미등록을 표시합니다.
- **규칙 실행**: 카드 종류나 회원 판정에 따라 환영 화면, 기록, 회원 화면 또는 다른 앱을 엽니다.
- **암호화 기록**: 읽은 정보와 판정, 적용 규칙을 기기 안에 최대 10,000건 저장합니다.
- **기록 관리**: 목록·상세 조회, CSV 내보내기, 전체 삭제를 지원합니다.
- **키오스크**: 전체 화면, 앱 고정, 관리자 PIN으로 출입 확인 화면을 운영합니다.

## 리더 연결 방식

1.2.0부터 Magisk 모듈 `sunmi_payhw`가 필요하지 않습니다. 1.3.0부터 아래 순서로 리더를 고릅니다.

1. **카드 리더 서비스가 있을 때**: 별도 드라이버 앱 `com.toss.cardreader.service`를 통해 읽습니다. 다른 앱도 같은 서비스로 리더를 쓸 수 있습니다. [docs/reader_service_api.md](docs/reader_service_api.md)
2. **결제 하드웨어 서비스가 있을 때**: 순정 `SunmiPayHardwareService`(`com.sunmi.pay.hardware_v3`)에 연결해 기존과 같이 사용합니다.
3. **둘 다 없을 때**: 앱이 리더의 보안 프로세서(SP)와 UART `/dev/ttyS3`로 직접 통신합니다. 통신 규격은 [docs/sp_protocol.md](docs/sp_protocol.md)에 정리했습니다.

두 경로 모두 같은 화면과 기록 기능을 사용합니다. 직접 연결은 서비스가 없는 상태의 토스프론트 실기기에서 IC 삽입 감지, ATR·APDU 읽기, 마그네틱 읽기로 확인했습니다.

### 안전 범위

직접 연결은 카드 읽기 명령 5개만 보낼 수 있습니다. 코드에서 다른 명령은 만들 수 없고, 단위 테스트가 이 허용 목록을 검사합니다.

| 허용 명령 | 용도 |
| --- | --- |
| IC 상태 확인 | 카드 삽입 여부 |
| IC 전원 켜기 | ATR 읽기 |
| IC APDU 교환 | EMV 공개 정보 읽기 (SELECT, READ RECORD, GET RESPONSE, GPO) |
| IC 전원 끄기 | 읽기 종료 |
| 마그네틱 읽기 | 트랙 1·2·3 |

펌웨어 다운로드·업그레이드, 키·인증서 저장과 삭제, 기기 인증 정보, 애플릿, 시스템 설정, 리셋 라인 제어, PIN 입력 명령은 보내지 않습니다. 직접 연결 로그에는 명령 번호와 결과 코드만 남기고 카드 데이터는 기록하지 않습니다.

## 사용 가능한 카드

| 종류 | 지원 상태 | 읽는 정보와 조건 |
| --- | --- | --- |
| 접촉식 IC 카드 | 지원 · 실기기 확인 | ATR, EMV 공개 레코드, 카드번호, 유효기간, 소유자, AID, 앱 이름 등. 카드가 제공하는 값만 읽습니다. |
| 마그네틱 카드 | 지원 · 실기기 확인 | 트랙 1·2·3과 트랙에서 추출한 카드번호, 유효기간, 소유자, 서비스 코드 |
| 삼성페이 | **지원 · 2026-11-22 실기기 확인** | MST 방식으로 마그네틱 리더에 전달된 것으로 추정합니다. 실제 전달 경로는 기기 로그로 확인하지 않았습니다. |
| NFC·비접촉식 카드 | 미확인 | 이 기기에서 NFC 리더의 존재와 동작을 확인하지 않았습니다. |

삼성페이 동작 확인은 시험한 기기와 환경에서의 결과입니다. 모든 휴대전화나 카드 조합의 동작을 보장하지 않습니다.

## 설치

### 전제 조건

1. PC에서 `adb`를 사용할 수 있고, 대상 기기의 USB 디버깅이 허용되어 있어야 합니다.
2. GitHub Releases에서 `toss-front-card-app-1.3.0.apk`를 다운로드합니다. 카드 리더 서비스를 함께 쓰려면 [Toss-CardReader-Service](https://github.com/AkaKSR/Toss-CardReader-Service/releases) Releases의 서비스 APK도 설치합니다(선택).

Magisk 모듈과 결제 하드웨어 서비스는 필요하지 않습니다. 기존에 `sunmi_payhw` 모듈과 서비스(검증 버전 `3.3.357`)를 설치했다면 그대로 두어도 되며, 이 경우 앱은 서비스를 사용합니다.

Sunmi 결제 하드웨어 서비스의 APK나 라이브러리는 이 저장소에 포함하지 않습니다. 서비스를 다른 버전으로 임의 교체하면 SP 펌웨어가 자동 업데이트될 수 있으므로 기존 하드웨어 구성을 유지하세요.

### APK 설치와 권한

아래 명령은 `adb`에 대상 기기 한 대가 연결된 상태를 기준으로 합니다.

```sh
adb install -r toss-front-card-app-1.3.0.apk
adb shell appops set com.toss.cardapp SYSTEM_ALERT_WINDOW allow
adb shell pm grant com.toss.cardapp android.permission.POST_NOTIFICATIONS
adb shell dumpsys deviceidle whitelist +com.toss.cardapp
adb shell am start -n com.toss.cardapp/.ui.ReaderActivity
```

- **다른 앱 위에 표시**: 백그라운드에서 리더 화면을 열 때 필요합니다. 앱 설정의 허용 버튼으로도 설정할 수 있습니다.
- **알림**: 카드 감지 대기 서비스의 상태를 표시합니다.
- **배터리 최적화 예외**: 대기 서비스의 실행을 돕습니다.

1.0.0~1.2.0과 같은 서명 키로 만든 APK이므로 기존 앱 위에 업데이트할 수 있습니다. 기록·회원·규칙은 유지됩니다.

## 버전 기록

| 버전 | 날짜 | 변경 요약 |
| --- | --- | --- |
| 1.3.0 (versionCode 4) | 2026-11-23 | 별도 카드 리더 서비스 앱(`com.toss.cardreader.service`)을 먼저 쓰고, 없으면 Sunmi 결제 서비스, 그다음 직접 연결 순으로 리더를 고릅니다. 공용 드라이버를 `reader` 모듈로, 연결 라이브러리를 `client` 모듈로 분리했습니다. |
| 1.2.0 | 2026-11-22 | Magisk 모듈 없이 `/dev/ttyS3` 직접 연결, 이미 읽은 IC 카드는 제거 안내 |
| 1.1.0 | 2026-11-22 | 공개 첫 버전, 삼성페이 실기기 확인 |

- 1.3.0 APK는 커밋 `c3f53e4`(태그 `v1.3.0`)에서 빌드한 파일입니다. 그 뒤 `main`에 들어간 리더 수정(링크를 다시 열 때 프레임 번호를 00부터 시작, 마지막 클라이언트가 나갈 때마다 리더 닫기)은 카드 리더 서비스 1.0.2에 들어 있고, 앱의 직접 연결 경로에는 다음 앱 버전부터 반영됩니다.
- 카드 리더 서비스 소스와 릴리스는 [AkaKSR/Toss-CardReader-Service](https://github.com/AkaKSR/Toss-CardReader-Service)에서 따로 배포합니다. 이 저장소의 `service` 모듈과 같은 코드입니다.

## 사용법

### 일반 모드

1. 런처에서 **카드 리더**를 엽니다.
2. IC 카드를 꽂거나 마그네틱 카드를 긁어 읽은 정보를 확인합니다.
3. 상단의 **기록·회원·규칙·설정**에서 데이터를 관리합니다.

회원은 최근에 읽은 카드 또는 직접 입력한 값으로 등록합니다. 비교 기준은 카드번호, 소유자 이름, 트랙, ATR, AID 중에서 선택합니다. 규칙은 위에서부터 처음 맞는 항목 하나만 실행합니다.

### 카드 감지 시 자동 실행

설정의 **카드 넣으면 자동 실행**은 기본으로 켜져 있습니다. 대기 중에는 **카드 자동 실행 켜짐** 알림이 표시됩니다.

- 앱을 처음 열거나 업데이트·재부팅하면 대기 서비스를 시작합니다.
- 앱 화면을 보고 있을 때는 화면이 리더를 사용하고, 홈으로 나가면 서비스가 이어받습니다.
- 같은 IC 카드가 꽂힌 채로 화면을 반복해서 열지 않도록 카드가 빠질 때까지 기다립니다.
- 화면을 띄울 권한이 없으면 마그네틱 감지 결과는 기록에만 저장될 수 있습니다.

**Android 설정에서 강제 종료하면 자동 실행과 부팅 수신도 중단됩니다. 앱을 직접 한 번 다시 열어야 대기를 재개합니다.**

### 키오스크와 관리자 PIN

1. 설정에서 **관리자 PIN**을 4~8자리로 정합니다.
2. **키오스크** 또는 **키오스크 시작**을 누릅니다.
3. 처음 표시되는 Android 앱 고정 안내를 확인합니다.
4. 나갈 때는 오른쪽 아래 **관리자**를 누르고 PIN을 입력합니다.

키오스크에서는 뒤로 가기를 막고 결과를 15초 뒤 지웁니다. 관리 화면이나 다른 앱으로 이동하는 규칙도 실행하지 않습니다. 기본 잠금은 Android 앱 고정입니다. 확인 창 없는 완전 잠금은 별도의 기기 소유자 구성이 필요합니다.

## 데이터 보안

- **기기 내 암호화**: 기록·회원·규칙은 Android Keystore의 AES-256-GCM 키로 암호화합니다. 키는 기기 밖으로 내보내지 않습니다.
- **자동 외부 전송 없음**: 앱에 인터넷 권한이 없습니다. 사용자가 직접 선택하는 CSV 내보내기만 기기 밖으로 데이터를 옮길 수 있습니다. 내보낸 CSV는 평문입니다.
- **백업 제외**: 앱 데이터는 백업과 기기 이전 대상에서 제외합니다.
- **관리자 PIN**: 솔트를 포함한 PBKDF2 해시로 저장합니다.
- **화면 표시**: 카드번호는 기본으로 전체 표시합니다. 설정에서 가릴 수 있지만, 암호화 기록에는 전체 정보가 저장됩니다. 소유자 이름과 유효기간은 설계상 화면에서 가리지 않습니다.
- **앱 로그**: 카드 원문을 logcat에 기록하지 않습니다.

실제 카드 데이터, 화면 캡처, 검증 기록, 서명 키, 로컬 설정과 APK는 공개 소스 트리에서 제외합니다. 테스트에는 실제 카드에서 수집하지 않은 합성 fixture를 사용합니다.

## 제한 사항

- 결제 앱이 아니며 결제 승인이나 PIN 검증을 하지 않습니다.
- IC 읽기는 공개 EMV 정보에 한정됩니다. GPO 과정에서 카드의 거래 카운터가 증가할 수 있습니다.
- 카드가 제공하지 않거나 접근을 허용하지 않는 정보는 읽을 수 없습니다.
- NFC는 확인되지 않았습니다. 삼성페이 확인 결과를 NFC 지원으로 해석하면 안 됩니다.
- Android 설정에서 강제 종료하면 자동 실행이 멈춥니다. 앱을 직접 한 번 다시 열어야 재개됩니다.
- 소유자 이름과 유효기간은 설계상 화면에서 가리지 않습니다. 카드번호 가리기 설정은 카드번호에만 적용됩니다.
- 직접 연결은 토스프론트 PLF02WH의 `/dev/ttyS3`에서만 확인했습니다. 다른 기기나 펌웨어에서는 동작을 보장하지 않습니다.
- 여러 앱이나 서비스가 동시에 리더를 사용하면 충돌할 수 있습니다. 직접 연결 중에는 다른 프로그램이 `/dev/ttyS3`를 열지 않게 하세요.
- 화면 표시부터의 내부 처리 시간과 실제 카드를 대는 순간부터의 시간은 다릅니다. 물리 동작부터 감지까지의 지연은 계측하지 않았습니다.

## 소스 빌드

JDK 21과 Android SDK의 Android 34 플랫폼·빌드 도구를 준비하고 SDK 위치를 설정합니다.

```sh
./gradlew test assembleRelease
```

- 모듈: `app`(카드 리더 앱), `service`(카드 리더 서비스), `client`(연결 라이브러리 AAR), `reader`(공용 드라이버), `testclient`(시험 앱).
- 카드 리더 앱은 기존 키(`keystore-cardapp.properties`), 서비스와 시험 앱은 새 릴리스 키(`keystore.properties`)로 서명합니다. 둘 다 Git에서 제외합니다.

- 결과 파일: `app/build/outputs/apk/release/app-release.apk` 등. 서명 설정 파일이 없으면 디버그 키를 사용합니다.
- 디버그 빌드의 패키지는 `com.toss.cardapp.debug`이며, 합성 카드 주입 기능이 포함됩니다. 배포용 릴리스에는 이 기능이 없습니다.
- 디버그와 릴리스를 동시에 대기시키면 같은 리더를 다투므로 한쪽만 실행하세요.

## 제거

키오스크를 사용 중이면 먼저 관리자 PIN으로 나갑니다. 기기 소유자로 별도 구성했다면 해당 관리 정책부터 해제하세요.

```sh
adb uninstall com.toss.cardapp
adb uninstall com.toss.cardapp.debug
```

두 번째 명령은 디버그 빌드도 설치했을 때만 필요합니다. 앱을 제거하면 암호화 기록과 기기 내 키가 함께 삭제됩니다.
